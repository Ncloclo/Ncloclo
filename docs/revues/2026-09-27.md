# Revue hebdomadaire TrendGuard — 2026-09-27

## Verdict

**Ne rien changer côté stratégie ni risque.** Les tests passent (261/258,
3 tests ajoutés), les paramètres en place respectent les limites (1 % par
trade, 6 % cumulé, 8 positions, stops et kill-switch actifs), et aucune
actualité de la semaine ne touche les 21 cryptos suivies. J'ai corrigé
trois petits défauts de code trouvés en revue (aucun n'a jamais mis en
danger une position réelle — détails plus bas) : à fusionner si les tests

de cet environnement cloud si tu veux que les prochaines revues
automatiques puissent réellement joindre Binance (voir plus bas) — sinon,
rien à faire.

## Limite majeure de cette revue : accès réseau

Cette session cloud n'a pas pu joindre Binance (`api.binance.com`,
`data-api.binance.vision`) ni les sites d'actualités (Google Actualités,
CoinDesk, Cointelegraph, Decrypt, Fear & Greed) : la politique réseau de
l'environnement bloque ces domaines (refus 403 à la passerelle), que ce
soit pour `market_watch.py`, `trendguard_bot.py diagnose` ou
`strategy_lab.py`. Ce n'est pas le blocage géographique 451 déjà corrigé
par le dernier commit du dépôt (« Données publiques Binance partagées ») :
ici, la passerelle réseau de cet environnement coupe l'accès avant même
d'atteindre Binance, quel que soit l'hôte.

Conséquence concrète cette semaine :

- `market_watch.py --no-ai` : 0 actualité collectée, sources injoignables.
- `trendguard_bot.py diagnose` : n'a pas pu tourner (mêmes domaines
  bloqués) — aucun chiffre frais de santé de la stratégie ci-dessous.
- `strategy_lab.py` : n'a pas pu télécharger l'historique Binance, donc
  pas de nouveau tournoi de stratégies cette semaine.

J'ai remplacé la collecte automatique par une recherche web manuelle (voir
ci-dessous, sources citées), mais je n'ai aucun chiffre de portefeuille
réel ni de nouveau backtest à te présenter. Pour que les prochaines revues
automatiques fonctionnent pleinement, il faudrait élargir l'accès réseau
de cet environnement cloud (menu de l'environnement ▸ Accès réseau) pour
autoriser au moins `data-api.binance.vision`, `api.binance.com` et les
domaines d'actualités listés dans `market_watch.py`.

## Revue de code

Le code est dans un état solide : gestion des secrets soignée (clés
saisies masquées, fichier `.env` en droits restreints, jamais loggées en
clair), positions toujours protégées à deux niveaux, veille IA qui ne
peut ni acheter, ni vendre, ni poser de veto. La page d'animation échappe
correctement les données de marché (`textContent`, pas d'`innerHTML`) et
ne fait aucune requête réseau imprévue. Aucun défaut critique ni majeur.

J'ai corrigé trois défauts mineurs trouvés en lecture, avec tests ajoutés
(261 tests passent, contre 258 avant) :

1. **`market_watch.py`** : une IA pouvait justifier un événement sur une
   crypto en citant l'URL d'un article réellement collecté mais qui ne
   parlait pas de cette crypto (seule l'appartenance de l'URL à la liste
   des sources était vérifiée, pas son contenu, contrairement à une
   citation numérotée « #n » qui vérifie déjà le titre). Corrigé : une
   source citée par son URL doit maintenant, comme une citation
   numérotée, nommer la crypto dans le titre collecté. Sans effet sur le
   trading (canal consultatif uniquement), mais referme un trou dans la
   garde-fou déjà documentée dans le README.
2. **`diagnostics.py`** (`check_portfolio`) : une division par l'equity
   du portefeuille sans protection contre une equity nulle ou négative
   aurait fait planter `diagnose` (erreur, pas de rapport) dans un cas
   rare (compte réel jamais encore passé par une décision, mais avec des
   positions déjà en base). Corrigé par un plancher minimal sur l'equity
   utilisée au dénominateur ; aucun effet sur les chiffres affichés en
   temps normal.
3. **Tests manquants** repérés par la revue, maintenant comblés : les
   fonctions `v29.make_public_binance`/`PublicKlines.fetch_time` (ajoutées
   au commit précédent, pour lire Binance sans clé API) n'avaient pas de
   test sur l'heure du serveur ni sur une panne réseau ; le garde-fou qui
   empêche de remonter un stop catastrophe simulé au-dessus du marché
   (`_raise_paper_disaster`, `trendguard_bot.py`) n'avait pas de test
   dédié. Aucun bug trouvé dans ces deux cas — seulement des lacunes de
   couverture, désormais fermées.

## Limites de cette revue

- Revue conduite depuis un environnement cloud sans accès à Binance ni
  aux sites d'actualités (voir plus haut) : ni diagnostic, ni laboratoire
  de stratégies n'ont pu tourner cette semaine ; la partie marché vient
  de recherches web manuelles, pas de la veille automatisée du bot.
- `requirements-docker.txt` cible Python 3.12 (image Docker) ; cet
  environnement de revue tourne en Python 3.11 et a dû utiliser
  `requirements.txt` (plages de versions) pour installer les dépendances
  et lancer les tests. Sans effet sur le bot lui-même (Docker reste en
  3.12), mais à savoir si une prochaine revue automatique échoue à
  l'installation.
- Comme toujours, aucune garantie que les performances passées se
  répètent ; le taux de réussite (35-49 %) reste normal et attendu, ce
  n'est pas un signal d'alerte en soi.
